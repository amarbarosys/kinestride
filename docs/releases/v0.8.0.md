**Released:** 2026-10-12 · **Commit:** `01fb255` · **Previous:** [v0.7.0](v0.7.0.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
65,536 articulated bodies, each with 74 degrees of freedom, contacts and 50 actuators, step together in 66.7 ms
on one AMD RX 7900 XTX. Kinestride is batched GPU physics in Mojo: one GPU thread per body, any MuJoCo MJCF model
as input, and every stage checked against MuJoCo 3.9.0 with a planted bug that the check must catch.

## Highlights

- A mocap clip drives a physics character: CMU BVH in, a 70 kg MJCF character and a reference clip out (`bvh`), and
  `track` makes 64 Kinestride bodies follow it with joint servos and a root assist. On the 10_01 kick, Kinestride's
  run matches MuJoCo's run of the same loop to 0.67 µm mean body position over 800 frames, with identical contacts.
- Motion metrics between any two clips (`motion_metrics`): position, rotation, spectrum (NPSS), foot skate, contact
  mismatch.

## Known limits

- The root assist does much of the balancing: with a softer weld (`ASSIST=0.02`) the same loop tracks at 0.090 m /
  0.303 rad. The servos alone do not yet balance these clips.
- 61-62 ms per frame (4 steps, 64 animals), measured on a card shared with other queued jobs; not yet optimized.
- Reference contacts are a height + speed estimate, sim contacts are solver contacts: contact_err between them is
  reported, not barred.
- Plane-capsule contact is not ported, so bones are convex meshes.
- Checked on one GPU (RX 7900 XTX).

## Upgrade / run

```
tools/assets.sh
kinestride/check.sh motion; kinestride/check.sh bvh
gpu-wait run --priority 90 --timeout 2400 -- kinestride/check.sh track
```
Any CMU-style BVH: `bvh mjcf CLIP.bvh OUT.xml`, `bvh clip CLIP.bvh OUT`, then the `track` steps in `docs/MOTION.md`.

# kinestride v0.5.0

**Released:** 2026-10-12 · **Commit:** `8ad915a` · **Previous:** [v0.4.0](v0.4.0.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
65,536 articulated bodies, each with 74 degrees of freedom, contacts and 50 actuators, step together in 66.7 ms
on one AMD RX 7900 XTX. Kinestride is batched GPU physics in Mojo: one GPU thread per body, any MuJoCo MJCF model
as input, and every stage checked against MuJoCo 3.9.0 with a planted bug that the check must catch.

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- Bodies of different trees in one model can now touch and be tied together: contact pairs, connect/weld/joint
  equalities, spatial and fixed tendons and tendon limits may join two animals (Newton solver, pyramidal cone, Euler
  integrator), each still checked against MuJoCo 3.9.0.
- An endless human-scale city: `city.mojo` builds it from a seed and a global cell, and the renderer draws it with
  `-DCITY=1`.
- World-part meshes and terrain run in Mojo (`assets.mojo`, `world.mojo`); the Python versions stay as oracles.

## Changes

### Added
- Coupling across trees in one model: export no longer refuses a pair, tendon or equality that joins two trees; it
  refuses only such coupling outside Newton + pyramidal + Euler (`check.sh cross`, fixture `models/cross_world.xml`).
- `model.shifted()` (a model moved along x, for precision placements) and the `CROSS_MIN` guard in `model.check`.
- `city.mojo` and render `-DCITY=1`; `assets.mojo`; terrain through `world.mojo`.
### Changed
- `model.check` compares ten_length, ten_velocity and ten_J on every stage of a model with spatial tendons (the engine
  always writes them; such stages used to fail on output size).

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- Cross-tree coupling is gated with the Newton solver, the pyramidal cone and the Euler integrator only; CG, PGS, RK4,
  implicit, implicitfast and the elliptic cone are refused at export for such models.
- Mesh-mesh pairs are not ported, so two mesh bodies (fly and spider) still cannot touch each other; primitive and
  sphere pairs can.
- Pairs are static (listed at export); there is no broadphase across trees.
- Checked on one GPU (RX 7900 XTX).

## Upgrade / run

<!-- Exact commands. Migrations, new deps, service restarts, config keys. "None" if nothing changed. -->
```
gpu-wait run --priority 70 --timeout 3600 -- kinestride/check.sh cross
```
Models that combine trees need explicit `<pair>` elements between them (export refuses contype/conaffinity overlap).

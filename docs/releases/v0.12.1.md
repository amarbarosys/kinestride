# kinestride v0.12.1

**Released:** 2026-10-26 · **Commit:** `691372e` · **Previous:** [v0.12.0](v0.12.0.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
65,536 articulated bodies, each with 74 degrees of freedom, contacts and 50 actuators, step together in 66.7 ms
on one AMD RX 7900 XTX. Kinestride is batched GPU physics in Mojo: one GPU thread per body, any MuJoCo MJCF model
as input, and every stage checked against MuJoCo 3.9.0 with a planted bug that the check must catch.

## Highlights

- Muscle-driven GPU builds no longer overrun host memory: the first-step copy wrote every scratch row into a list sized
  for the outputs only.
- A bench or check run at 65,536 bodies needs 1.99 GB of host memory instead of 9.27 GB.

## Changes

### Added
- `probes/copy_size_probe.mojo`: shows that `enqueue_copy(host_ptr, device_buffer)` copies the whole buffer.
- `tools/permute_bench.py`: a bench directory in another lane order (random or sorted by contact set), and the check that
  its outputs equal the original after un-permuting.
### Fixed
- `smooth.mojo` host copies go through `rows()`, a sub-buffer of exactly the rows wanted: the muscle first-step copy
  (heap overrun of (NROW - NOUTX) x F x 4 bytes) and the bench output copy (every row, now the outputs only, all rows only
  with DUMP).

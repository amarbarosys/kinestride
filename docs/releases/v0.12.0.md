# kinestride v0.12.0

**Released:** 2026-10-23 · **Commit:** `a07d3d0` · **Previous:** [v0.11.0](v0.11.0.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
65,536 articulated bodies, each with 74 degrees of freedom, contacts and 50 actuators, step together in 66.7 ms
on one AMD RX 7900 XTX. Kinestride is batched GPU physics in Mojo: one GPU thread per body, any MuJoCo MJCF model
as input, and every stage checked against MuJoCo 3.9.0 with a planted bug that the check must catch.

## Highlights

- Thirteen MuJoCo features that export used to refuse now simulate, each checked against MuJoCo 3.9.0 with planted
  bugs: friction loss (dof and tendon), torsional and rolling friction (condim 4/6), tendon equalities, runtime
  equality switching, direct solref on equality and limit rows, joint actuator force limits, contact pairs between two
  free bodies or two animals, PGS and CG over every row kind, the elliptic cone under RK4 and implicitfast, and
  margin-0 mesh-mesh contact by MuJoCo's polygon clipping.
- The living-world renderer: smooth B-spline ground, six tree species with trunks and crowns, grass and heather blades,
  shorelines and water, clouds, aurora, gulls, trails, temporal AA and a film finish (`render -DLIVING=1`).
- Muscle-driven bodies: an excitation-driven tendon muscle engine with an analytic oracle, feeding game stamina.
- Streamed terrain: a table-backed heightfield (HTAB) an app can rewrite between steps; `track` runs HTAB models.

## Changes

### Added
- check.sh stages: `solref_direct`, `actfrc`, `tendon_eq`, `eqact_runtime`, `frictionloss`, `tendon_friction`,
  `condim46`, `freefree`, `pair_cross_animal`, `pgs_full`, `cg_full`, `elliptic_int`, `meshmesh0` (48 -> 61 stages).
- `kinestride/port_queue.tsv` rows for every former refusal; private note `FLEX` (flex in six stages, about 2,400 LOC).
- `render.frame()` fills a caller's profile table (ms per pass under `-DPROF=1`).
- `tools/lane_prep.sh` (worktree prep for lanes); `tools/friction_zones.py`.
### Changed
- Export no longer refuses the thirteen features above; `docs/ENGINE_REFERENCE.md` and the README refusal list follow.
- PGS matches MuJoCo in MuJoCo's efc order (equality block first, then contacts pair by pair); islands from a
  union-find over trees.
### Fixed
- `-DEQACT=1` reads one ctrl row per MuJoCo equality, not one per equality-block entry (limit and friction rows used to
  shift the switches).
- `tools/assets.sh` fills the 26 flight meshes flight-body leaves out; `check.sh living` reads living-world's `world/`.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- `check.sh cone_hfield` FAILs (fly, noslip 5: one state differs in ncon, qacc 2.4e-2): already red before this release, cause open.
- `check.sh living` FAILs: `living_check.mojo` reads living-world's old world.bin cell layout.
- Noslip after PGS with convex pairs stays refused (one arena state of 64 is 0.28 off MuJoCo).
- Plane-mesh: an edge-down hull with two vertices within 1e-5 in depth gives 2 contacts where MuJoCo gives 1.
- Flex (soft bodies) is planned, not ported. Engine run only on gfx1100.
- `tools/check_all.sh`'s one GPU job (3600 s) is too short for 61 stages; chunk or scale it.
